3 CONCEPTS:
Combat Rotation Instrument

Concept 1: "Signal Wire"
Screen: A single horizontal timeline spine runs across the center of the screen — thin, glowing, pale cyan. Snapshots are vertical pulses rising above and below this spine like an oscilloscope. Above: damage events. Below: resource consumption. Character switches are marked by a subtle color-shift along the spine itself — each character owns a hue (teal, amber, violet).

Time: The spine is time. It scrolls horizontally. The viewport is roughly 15–20 snapshots wide. The current focus point has a bright vertical hairline cursor. Past fades to lower opacity. Future is dim but visible, like radar echoes.

DPS & Impact: High-damage snapshots produce taller pulses with a brief radial bloom — like a signal spike on a monitor. The pulse height maps to raw damage. A faint trailing glow lingers for 0.3s after big hits. Crits have a sharper, whiter peak. The DPS average is a slow-moving sine wave underneath, ghosted.

Buffs/Debuffs/Resources: Buffs appear as thin horizontal tether lines stretching from their activation point forward along the spine until expiry — color-coded, slightly translucent. When you hover a buff line, every snapshot it touches subtly brightens. Debuffs hang below the spine as inverted, red-shifted versions. Resources (Energy, Forte, etc.) are stacked micro-bars at each snapshot position — like tiny vertical gauges embedded into the spine, almost like LED indicators on hardware.

Hover/Select: Hovering a snapshot causes tether lines to extend outward to every connected element — the buff that was active, the resource state, the character. These lines animate in with a quick elastic ease. The snapshot lifts slightly (2px) and a detail panel materializes to the right — not a popup, but a smooth slide-in pane with glowing borders. Everything else dims to 40% opacity.

Motion: Precise. Mechanical. Like a high-end audio visualizer. Easing is tight spring curves. Nothing bounces — everything snaps with a slight overshoot then settles. Scrolling the timeline feels like scrubbing a waveform.

Aesthetic: Dark background (#0a0e14). Monospaced micro-type. Thin 1px lines. Glow effects are additive blending — cyan, amber, soft white. Minimal use of fills. Everything is lines, pulses, and light. Feels like a military-grade signal analyzer.

Concept 2: "Orbital Ring"
Screen: The rotation is literal — snapshots are arranged in a large circular arc filling 70% of the viewport. The circle represents the full rotation cycle. Each snapshot is a node on the ring — a small diamond or hexagon. The currently selected node is enlarged and pulled slightly toward center. The center of the ring is a live readout zone: character portrait (silhouette-style), current DPS, active buffs displayed as orbiting particles.

Time: Time flows clockwise. A faint animated dash pattern traces the ring's circumference like a loading indicator, showing progression. Character segments own arcs of the ring — visually distinguished by a subtle background gradient band behind their section. Transition points between characters have a brief "handoff" gap with a small spark animation.

DPS & Impact: Each node's size and inner brightness scales with damage dealt. Low-damage nodes are dim, small. High-damage nodes pulse with a warm amber/white core. The ring itself thickens at high-DPS stretches — like a vessel carrying more energy. A radial bar chart in the center updates to show DPS over the last N snapshots as you scrub around the ring.

Buffs/Debuffs/Resources: Buffs are concentric inner rings — thinner, translucent arcs that span their duration. Hovering a buff arc highlights every node it covers. Resources are shown as a secondary ring just inside the main one — segmented gauge style, color fills indicating current levels. Overcaps flash briefly with a warning amber pulse. Debuffs/DoTs are shown as outer ring thorns — small angular protrusions on the exterior.

Hover/Select: Selecting a node causes radial lines to shoot from it to the center readout, which transitions to show that snapshot's full detail. Connected buffs illuminate their arcs. A subtle ripple emanates outward from the selected node. Neighboring nodes shift slightly apart to give breathing room.

Motion: Rotational, gravitational. Things orbit, sweep, and arc. No linear translations — everything curves. Easing is smooth and planetary. The ring itself can be slowly rotated by drag gesture, giving a tactile globe-like feel.

Aesthetic: Deep navy background with subtle radial gradient toward center. The ring glows softly — like a holographic projector. Colors are cool-dominant: steel blue, ice white, with warm amber for damage spikes. Thin line weights (0.5–1px). Typography is geometric sans-serif, small, placed tangentially along curves. Feels like a sci-fi tactical display from a mech cockpit.

Concept 3: "Tether Field"
Screen: No single axis. Snapshots are laid out in a flowing, left-to-right river formation — not a strict grid, not a line. They meander slightly, like a path through space. Each snapshot is a small circular node. Tether lines visibly connect sequential nodes, and also connect nodes that share buffs, character, or resource thresholds — creating a web of relationships. The background is near-black with a faint dot grid (like graph paper in space).

Time: Time flows left to right, but the vertical position of each node is driven by its "intensity" — high-DPS moments drift upward, recovery/setup moments sink lower. This creates a topographical landscape of the fight. Peaks and valleys are immediately readable. A ghosted horizontal baseline shows "average" intensity.

DPS & Impact: The tether lines between high-damage nodes glow brighter and thicker — like power cables under load. Crit chains cause a brief cascade animation along connected lines, like electricity traveling. The nodes themselves have a radial gradient: warm core = high damage, cool core = utility/setup. A faint heatmap wash behind the node field shows DPS density — warmer bands where damage clusters.

Buffs/Debuffs/Resources: Buffs are visualized as fields — soft, translucent rectangular zones behind the nodes they affect, with rounded edges and a gentle color fill (green-tinted for buffs, red-tinted for debuffs). Multiple overlapping buffs create layered translucency — visually showing buff stacking. Resources appear as tiny spark lines trailing behind each node — longer trails = more resource remaining. Overcap moments have the trail "breaking" with a small shatter particle effect.

Hover/Select: Hovering a node activates its tether network. Every line connected to it (sequential, buff-shared, character-shared) illuminates with a quick propagation animation — light traveling along the wire from the hovered node outward. Unrelated nodes fade to near-invisible. A detail panel appears anchored to the node — floating, with a subtle parallax offset as you move the cursor. The panel has no hard border — just a soft shadow and glass-morphic blur.

Motion: Organic but controlled. Like neural signals firing. Lines illuminate with traveling-light animations. Nodes breathe (subtle scale oscillation). Field zones fade in with soft gaussian expansion. Nothing snaps — everything flows with 300–500ms durations and cubic-bezier easing. Feels alive but calm.

Aesthetic: Almost-black background (#08090d) with a 1px dot grid at 5% opacity. Node colors shift per character: teal, warm gold, soft rose. Tether lines are 1px, white at 20% opacity by default, brightening to 80% on activation. Typography is thin-weight, slightly warm white, with generous letter-spacing. The overall feel is like a constellation map crossed with a neural network visualization — cerebral, beautiful, slightly haunting.

My recommendation: Concept 3 ("Tether Field") is the most aligned with Wuthering Waves' tether identity — it literally visualizes cause-and-effect as connected tension lines, and the intensity-driven vertical positioning makes the fight's rhythm immediately spatial. Want me to build it?

Snapshots are stacked nodes along the column (time flows top→bottom).

Buffs/debuffs are concentric arcs or overlay bands along the column, maybe with subtle animation.

Hovering a snapshot triggers radial tethers connecting to adjacent columns (other characters) or resources.

Effect: Keeps the cinematic orbital feel, but now the table has readable columns per character, with spatial relationships and flowing motion intact.

3. Tether Field → Columned “Network Table”

Visual idea: Keep a top-to-bottom timeline per character (or combined in a multi-column view).

Each snapshot is a node in its row; tethers flow horizontally across columns connecting buffs, resources, or other snapshots.

High-DPS nodes can rise slightly above the row for visual emphasis.

Overlapping buffs/debuffs are layered with translucency behind each row.

Hovering a node lights up its tether network across the table.

Effect: Feels very much like a table, but the tether network brings the data to life. You get the readability of a table but retain a dynamic, signal-like, relational visual system.

All three concepts can adapt to a top-down, column/row structure with minimal tweaks:

Flip axes (horizontal → vertical)

Treat columns as character/resource lanes

Keep tethers, pulses, and dynamic interactions

Preserve intensity cues (spike height, glow, color)

Create a snapshot-based interface that is technically a table with rows and columns, but visually behaves like a living tether system console rather than a static data table.

The table is the structure, not the aesthetic.
It should feel like interacting with an active system displaying flowing combat signals, where data pulses, rotates, propagates, and responds to focus.

Structural Foundation (Important)

The layout uses rows and columns

Each row represents a snapshot

Columns represent channels (time, character state, resources, buffs, damage, etc.)

Scrolling is vertical

The table must remain readable and structurally sound

However:

Rows should not read as flat rectangles

Columns should not feel like static spreadsheet columns

Visual grouping, layering, and animation are encouraged

Visual Interpretation of Rows & Columns

Rows can behave like:

signal bands

data lanes

energy slices

system pulses

Columns can be visualized as:

vertical lanes of energy

stacked modules

embedded gauges

rotating or oscillating components inside the row

Avoid visible gridlines where possible — imply structure through spacing, glow, and alignment.

Animation & “Alive” Behavior (Key Priority)

Use animation to make the table feel active and intelligent:

Subtle continuous motion:

slow rotation of circular indicators

pulsing glows traveling through rows

oscillating resource bars

Reactive motion:

hovering a row sends light through connected columns

selecting a row slightly lifts it and increases signal intensity

adjacent rows respond with faint sympathetic motion

Propagation effects:

buffs and states visually flow across multiple rows

high-impact snapshots emit brief signal surges

Nothing should feel static — even idle elements should “breathe”

Animations should be controlled and elegant, not chaotic.

Data Density & Presentation

Numbers exist, but are not the visual focus

Prefer:

bars, rings, arcs, pulses, or glyphs

animated indicators over raw text

Detailed numeric data can:

fade in on hover

appear in overlays or side panels

be secondary to visual signal strength

The first impression should be system behavior, not analytics.

Interaction Model

Rows are interactive:

hover reveals relationships

selection increases brightness and motion

Hovering a row:

highlights related columns

animates tethers between affected data points

subtly dims unrelated rows

The table should feel like:

a console you’re probing

not a list you’re reading

Visual Style & Atmosphere

Dark, cinematic background

Additive light effects preferred over solid fills

Minimal borders

Clean, futuristic typography

Color used as signal, not decoration

Overall tone:
A calm but powerful internal system — precise, responsive, and alive.

Design Intent Clarification

This is not a static UI mockup.

It is a system display:

rows = moments

columns = channels

animations = activity

glow & motion = state

If the table were paused, it would still look interesting.
When interacted with, it should feel reactive and intelligent.

function vary(base: number, pct: number = 0.15): number {
  return Math.round(base * (1 + (Math.random() * 2 - 1) * pct));
}
function generateRotation(): Snapshot[] {
  const result: Snapshot[] = [];
  let id = 0;
  let time = 0;
  let energy = 40;
  let concerto = 0;
  let forte = 0;
  let conviction = 0;
  const cycles = 4;
  for (let c = 0; c < cycles; c++) {
    // Jiyan phase
    const jiyanBuffs = c > 0 ? ['Coordinated Attack'] : [];
    for (const tmpl of JIYAN_ACTIONS) {
      const dur = tmpl.dur * (0.9 + Math.random() * 0.2);
      const dmg = vary(tmpl.dmgBase);
      energy = Math.min(100, energy + dmg * 0.001 + 3);
      forte = Math.min(100, forte + 8 + Math.random() * 5);
      concerto = Math.min(100, concerto + 5 + Math.random() * 4);
      conviction = Math.min(5, conviction + (tmpl.dmgBase > 10000 ? 1 : 0));
      const buffs = [...jiyanBuffs];
      if (forte > 60) buffs.push('Forte Resonance');
      if (tmpl.action.includes('Liberation')) buffs.push('Resonance Liberation');
      const debuffs: string[] = [];
      if (tmpl.dmgBase > 15000) debuffs.push('Wind Shear');
      result.push({
        id: id++,
        character: 'Jiyan',
        action: tmpl.action,
        timeStart: Math.round(time * 100) / 100,
        timeEnd: Math.round((time + dur) * 100) / 100,
        damage: dmg,
        dps: Math.round(dmg / dur),
        energy: Math.round(energy),
        concerto: Math.round(concerto),
        forte: Math.round(forte),
        conviction,
        buffs,
        debuffs,
      });
      time += dur;
    }
    // Reset Jiyan resources on swap
    forte = 0;
    conviction = 0;
    concerto = 0;
    // Mortefi phase
    for (const tmpl of MORTEFI_ACTIONS) {
      const dur = tmpl.dur * (0.9 + Math.random() * 0.2);
      const dmg = vary(tmpl.dmgBase);
      energy = Math.min(100, energy + 4);
      concerto = Math.min(100, concerto + 12);
      const buffs: string[] = [];
      if (tmpl.action.includes('Liberation')) buffs.push('Resonance Liberation');
      if (tmpl.action.includes('Outro') || tmpl.action.includes('Liberation'))
        buffs.push('Coordinated Attack');
      result.push({
        id: id++,
        character: 'Mortefi',
        action: tmpl.action,
        timeStart: Math.round(time * 100) / 100,
        timeEnd: Math.round((time + dur) * 100) / 100,
        damage: dmg,
        dps: Math.round(dmg / dur),
        energy: Math.round(energy),
        concerto: Math.round(concerto),
        forte: 0,
        conviction: 0,
        buffs,
        debuffs: [],
      });
      time += dur;
    }
    concerto = 0;
    // Verina phase
    for (const tmpl of VERINA_ACTIONS) {
      const dur = tmpl.dur * (0.9 + Math.random() * 0.2);
      const dmg = vary(tmpl.dmgBase);
      energy = Math.min(100, energy + 3);
      concerto = Math.min(100, concerto + 10);
      const buffs: string[] = [];
      if (tmpl.action.includes('Liberation')) buffs.push('Healing Zone');
      if (tmpl.action.includes('Skill')) buffs.push('Healing Zone');
      result.push({
        id: id++,
        character: 'Verina',
        action: tmpl.action,
        timeStart: Math.round(time * 100) / 100,
        timeEnd: Math.round((time + dur) * 100) / 100,
        damage: dmg,
        dps: Math.round(dmg / dur),
        energy: Math.round(energy),
        concerto: Math.round(concerto),
        forte: 0,
        conviction: 0,
        buffs,
        debuffs: [],
      });
      time += dur;
    }
    concerto = 0;
    energy = Math.max(20, energy - 30);
  }
  return result;
}

const NODE_SPACING = 82;
const PADDING = 160;
const FIELD_HEIGHT = 600;
const BASELINE_Y = 370;
const CHARACTER_MAP = {
  Jiyan: 'jiyan',
  Mortefi: 'mortefi',
  Verina: 'verina',
} as const;
type CharKey = keyof typeof CHARACTER_MAP;
interface PositionedNode extends Snapshot {
  x: number;
  y: number;
  size: number;
  nd: number;
}
function getNodeY(nd: number): number {
  return BASELINE_Y - nd * 280 + (1 - nd) * 40;
}
function getNodeSize(nd: number): number {
  return 6 + nd * 16;
}
function curvePath(x1: number, y1: number, x2: number, y2: number): string {
  const mx = (x1 + x2) / 2;
  const dy = (y2 - y1) * 0.35;
  return `M ${x1} ${y1} Q ${mx} ${(y1 + y2) / 2 + dy} ${x2} ${y2}`;
}
interface BuffZone {
  buff: string;
  startX: number;
  endX: number;
  y: number;
  height: number;
  character: string;
}
function computeBuffZones(nodes: PositionedNode[]): BuffZone[] {
  const zones: BuffZone[] = [];
  const buffNames = ['Coordinated Attack', 'Resonance Liberation', 'Healing Zone', 'Forte Resonance'];
  buffNames.forEach(buffName => {
    let startIdx = -1;
    nodes.forEach((node, i) => {
      const hasBuff = node.buffs.includes(buffName);
      if (hasBuff && startIdx === -1) startIdx = i;
      if ((!hasBuff || i === nodes.length - 1) && startIdx !== -1) {
        const endIdx = hasBuff ? i : i - 1;
        const slice = nodes.slice(startIdx, endIdx + 1);
        if (slice.length >= 2) {
          const minY = Math.min(...slice.map(n => n.y)) - 35;
          const maxY = Math.max(...slice.map(n => n.y)) + 35;
          zones.push({
            buff: buffName,
            startX: nodes[startIdx].x - 25,
            endX: nodes[endIdx].x + 25,
            y: minY,
            height: maxY - minY,
            character: buffName === 'Healing Zone' ? 'verina' : buffName === 'Coordinated Attack' ? 'mortefi' : 'jiyan',
          });
        }
        startIdx = -1;
      }
    });
  });
  return zones;
}

  const nodes: PositionedNode[] = useMemo(() =>
    snapshots.map((s, i) => {
      const nd = s.damage / maxDamage;

    }), [maxDamage]);
  const fieldWidth = nodes.length * NODE_SPACING + PADDING * 2;
  const buffZones = useMemo(() => computeBuffZones(nodes), [nodes]);
  const connections = useMemo(() => {
    if (hoveredId === null) return new Set<number>();
    const hovered = nodes.find(n => n.id === hoveredId);
    if (!hovered) return new Set<number>();
    const set = new Set<number>();
    set.add(hoveredId);
    const idx = nodes.findIndex(n => n.id === hoveredId);
    if (idx > 0) set.add(nodes[idx - 1].id);
    if (idx < nodes.length - 1) set.add(nodes[idx + 1].id);
    nodes.forEach(n => {
      if (n.character === hovered.character && Math.abs(n.id - hoveredId) <= 10) set.add(n.id);
      if (n.buffs.some(b => hovered.buffs.includes(b)) && Math.abs(n.id - hoveredId) <= 14) set.add(n.id);
    });
    return set;
  }, [hoveredId, nodes]);
  useEffect(() => {
    if (scrollRef.current) {
      scrollRef.current.scrollLeft = (fieldWidth - window.innerWidth) * 0.3;
    }
  }, [fieldWidth]);
  const hoveredNode = hoveredId !== null ? nodes.find(n => n.id === hoveredId) ?? null : null;
  const handleEnter = useCallback((id: number) => setHoveredId(id), []);
  const handleLeave = useCallback(() => setHoveredId(null), []);

  const transitions = useMemo(() => {
    const pts: number[] = [];

      if (i > 0 && n.character !== nodes[i - 1].character) pts.push(i);

          {node.character === 'Jiyan' && node.conviction > 0 && (
            <ResourceBar label="Conv" value={node.conviction} max={5} color="var(--char-jiyan)" />
          )}
        </div>
        {/* Buffs */}
        {node.buffs.length > 0 && (
          <div className="flex flex-wrap gap-1 pt-1">
            {node.buffs.map((b, i) => (
              <span key={i} className="buff-pill">{b}</span>
            ))}
          </div>
        )}
        {/* Debuffs */}
        {node.debuffs.length > 0 && (
          <div className="flex flex-wrap gap-1">
            {node.debuffs.map((d, i) => (
              <span key={i} className="debuff-pill">{d}</span>
            ))}
          </div>
        )}
      </div>
    </motion.div>
  );
};
